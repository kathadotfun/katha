# JavaScript workspace setup

The workspace contains `apps/web`, `apps/api`, `packages/shared`, `packages/db`
and `packages/solana`, plus the Registry and Marketplace Anchor programs.
See [fresh setup](getting-started.md) for service startup and
[verification status](mvp-verification.md) for acceptance boundaries.

## Pinned tools

| Tool    | Version     | Project configuration                      |
| ------- | ----------- | ------------------------------------------ |
| Node.js | 24.21.0 LTS | `.nvmrc` and `package.json` engines        |
| pnpm    | 12.6.0      | `package.json` package manager and engines |

These are the selected, verified development versions. See the
[Node release](https://nodejs.org/en/blog/release/v24.21.0) and
[pnpm release metadata](https://registry.npmjs.org/pnpm/12.6.0).

## Select the runtime and install

From the repository root, using an existing nvm installation:

```bash
nvm install
nvm use
node --version
pnpm --version
```

Expected versions are `v24.21.0` and `12.6.0`. If pnpm is missing or another version
is selected, install the pinned version into the selected user-managed Node:

```bash
npm install --global pnpm@12.6.0 --no-audit --no-fund
pnpm --version
```

These setup commands use Bash. Allow pnpm's install scripts to install its native
executable; disabling them leaves a shell fallback that can fail when launched
directly by another process.

Then install from the committed lockfile:

```bash
pnpm install --frozen-lockfile
```

The generated lockfile has two YAML documents: package-manager dependencies
(pnpm and its platform executables), followed by the workspace resolution. The
second document records the root package and each app/package importer, including
packages with no runtime dependencies. Keep both documents and commit the generated
lockfile with manifest changes.

## Workspace configuration

- `package.json` marks the workspace private and pins both tools. The root package
  is not intended for npm publication.
- `.nvmrc` selects the project Node version through nvm.
- `pnpm-workspace.yaml` selects packages under `apps/*` and `packages/*`.
  The root package is also included. Rust programs are outside these globs.
- `engineStrict: true` checks Node compatibility during installation.
- `pmOnFail: error` rejects a mismatched pnpm version instead of automatically
  switching versions.
- `savePrefix: ''` saves newly resolved registry dependencies without a default
  version range. Dependency additions must still specify reviewed exact versions.
- `pnpm-lock.yaml` is generated by pnpm and belongs in Git. Commit it alongside
  every dependency change; frozen installs must succeed without changing it.

pnpm 12 reads these project settings from `pnpm-workspace.yaml`. `.npmrc` is
reserved for registry/authentication settings; credentials stay outside Git.
See [pnpm settings](https://pnpm.io/settings),
[CLI and engine settings](https://pnpm.io/settings/cli), and
[version prefix settings](https://pnpm.io/settings/other#saveprefix).

The web package supports local development, linting, route-aware type checking,
and production builds. The API package supports development, linting, type checking,
compilation, and graceful shutdown. The shared, database, and Solana packages
provide buildable TypeScript entrypoints. See the [Next.js guide](nextjs.md), [Hono API
guide](api.md), [shared package guide](shared-package.md), and [database package
guide](database-package.md), and [local service guide](local-services.md) for package
details and commands.
